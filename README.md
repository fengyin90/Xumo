# 续墨 · XUMO

**简体中文** · [English](README_EN.md)

给中文长篇小说用的续写工作台。桌面程序，写完几十万字之后，模型仍然记得人物是谁、
伏笔埋在哪里、笔法什么样。

## 它解决什么问题

用聊天框写长篇，写到二十万字左右一定会崩：模型忘了主角的师父姓什么，忘了前一章
刚把刀弄丢，忘了这本书的叙述是第三人称还是第一人称。你每开一轮都要重新解释一遍，
解释了它也记不住。

续墨把"让模型记得住"当成唯一的核心问题：设定、前情记忆、参考语料、上一章结尾
拼成一份完整上下文，每次请求整份注入；正文超出预算的部分自动压成前情提要，
追加进记忆。窗口永远装得下，故事不会因为窗口满了而断线。

## 和同类项目比

这个赛道不新，比续墨做得深的项目不少。下面只列机制上的差别，信息以各项目仓库自述为准。

| 项目 | 形态 | 长篇一致性手段 | 反 AI 腔 | 上手门槛 |
|---|---|---|---|---|
| **续墨** | 桌面 GUI，单文件便携 exe | 设定 / 记忆 / 语料 / 上文四层注入，超预算自动压缩 | 提示词层的文风禁区（见下） | 下载 exe 就能用 |
| InkOS | 命令行 | 7 个"真相文件" + 33 维度连续性审计 | 11 条确定性规则检测 + 定点修复，可接外部 AIGC 检测 | 需 Python 环境 |
| NovelScribe | pip 包 / CLI | 9 个智能体流水线，分层摘要，声称可到百万字 | 无专门机制 | `pipx install` |
| novel-agent | Web 应用 | LangGraph 编排 12 个智能体，ChromaDB 向量检索 | 无专门机制 | 需 Docker |
| AI-Writer | 命令行 | 无，靠本地模型自身上下文 | 无 | 需 GPU |
| KoboldAI / KoboldCpp | 浏览器前端 | World Info 词条手动维护 | 无 | 需本地模型与显存 |

续墨的短板很清楚：没有多智能体、没有审计闭环、没有向量检索、没有 Web 端。
它换来的东西是另外三样，也是这个表里唯一这么做的：

1. **装完就能用。** 打包出的是单文件 exe，作品数据存在 exe 同级的 `projects` 文件夹，
   换了电脑把 exe 拷过去，作品跟着走。上面几个项目都要先有 Python 或 Docker 环境。
2. **运行时的第三方依赖只有一个 PyQt6。** `ai.py` 里的 SSE 流式协议、退避重试、
   截断自动接续都是用标准库 `urllib` 手写的，没有 openai SDK、没有 requests、
   没有 LangChain。想改协议层不用先翻三层框架源码。
3. **改稿原地流式替换。** 选中一段文字直接改写，字在原地一句句长出来，
   眼睛不用离开上下文。中途按 Esc 保留已生成的部分；一个字都没出就失败，自动还原原文。

## 快速开始

需要 Python 3.10+。

```bash
pip install -r requirements.txt
python main.py
```

首次启动点右下角「引擎设置」，填 API Key。默认走 DeepSeek，
任何 **OpenAI 兼容接口**（`base_url` 以 `/v1` 结尾）都能用。

## 打包成 exe

```bash
pip install pyinstaller
build.bat
```

产物在 `dist/Xumo.exe`，单文件、免安装。`build.bat` 是 GBK 编码（配合 `chcp 936`），
改它的时候注意别存成 UTF-8。

## 主要功能

**写设定。** 右栏「设定」写个大概就行，哪怕只有一句"都市修仙，主角是外卖员"。
顶部一排**预设标签**点一下即并入设定（追加不覆盖，可叠加「都市」+「系统」+「爽文」），
内置 46 条覆盖常见题材与套路；也可把当前设定「存为预设」留作自己的标签。
点「补全设定」，AI 分六节（题材 / 人物 / 世界观 / 势力 / 专有名词 / 笔法）逐节补全，
后写的节会沿用前面已定的人名与设定，产出内部自洽的完整设定；点「取书名」拟几个候选。

**写正文。** 底部「续写」（Ctrl+Enter），或「一键生成」连写到你设的字数。
空稿自动走开篇模式：开头 300 字内交代清主角是谁、什么世界、处境如何，
设定里点名的核心要素（系统 / 金手指）会出现，而不是一串悬空的画面切片。

**自动审校。** 一键生成时，每写完一轮就独立审校一次（文风是否踩禁区、情节是否推进），
不合格按意见重写，复检通过才继续，最多 2 轮。可在引擎设置里关闭。
另有「更多 → 审校本章」手动出一份审校报告。

**设定自动跟上。** 一键生成写完后，程序通读全文，把新出现的人物、事件、伏笔并进设定。

**改稿。** 选中文字右键，挑润色 / 扩写 / 缩写 / 重写。

**中断与截断。** 单次回复被 `max_tokens` 硬切时，程序自动再请求一轮，
把已写内容回填，要求继续往下写、不要重复，最多接 4 轮。不会出现停在半句的情况。

**外观。** 三套配色（简约蓝 / 温馨粉 / 夜墨）。引擎设置里可开启**窗口流光边框** ——
默认七彩渐变绕边框流动并呼吸，也可切单色并自选主色。

**其他。** 写作统计（每章字数与占比）、历史版本回溯（回滚本身也可撤销）、
独立阅读窗口（逐章记忆滚动位置）、章节拖拽排序与合并、
文件拖入即成为参考语料、导出全书 / 单章 / 设定 / 项目备份。

完整操作表在 [CHANGELOG.md](CHANGELOG.md) 与程序内的「更多」菜单里。

## 上下文怎么拼

一次请求由四层拼成，顺序即优先级：

| 层 | 来源 | 作用 |
|---|---|---|
| 作品设定 | 你写的 + AI 补全的 + 自动分析 | 人物、世界、境界、势力、笔法，最高优先级 |
| 前情记忆 | 旧正文自动压缩而成 | 装下超出窗口的漫长前文 |
| 参考语料 | 你上传的设定 / 大纲 / 前作 | 硬性设定，不得违背 |
| 上文窗口 | 当前章末尾若干字 | 保证句子接得上 |

正文超过「上下文预算」（默认 5000 字）后，超出部分自动交给模型压成前情提要。
中栏底部显示预算占用。

## 反 AI 腔：为什么生成的东西不像 AI 写的

机器写小说最露馅的地方不止一处。`ai.py` 里有三份互不重叠的约束，
续写、开篇、补全设定、局部改写、审校五处提示词共用：

**`STYLE_BAN` —— 腔调。** AI 以为自己很有文采：一段里塞三个比喻，形容词堆成墙，
排比三连，"眼中闪过一丝""嘴角勾起一抹"这类套话轮着来。约束为一段之内比喻最多一处、
形容词不超过三个、禁止排比三连、禁止把情绪写成名词、禁止替读者抒情升华、
句子必须长短交错，外加一份套话黑名单。

**`NAME_BAN` —— 起名。** LLM 起名严重回归均值，不论什么题材都往"赵无极、叶凡、萧炎"
这一小撮名字上撞 —— 这已是生成文本的指纹。现点名约 20 个用烂的名字，禁止用
"龙 / 傲 / 天 / 霸 / 帝 / 神 / 魔"等字硬堆霸气名，要求贴合身份与时代。
只约束新引入的角色，前文已有的名字照用。

**`HUMAN_VOICE` —— 人与戏。** 针对机器写人最假的三处：
对话永远正确（现要求答非所问、打断、留白，每句台词要有目的）、
人物永远向善（反派要真做恶事，主角可以自私怯懦，做了错事可以毫无悔意）、
情节没有博弈（每段至少有人在算计，写信息差，允许撒谎演戏，反转要埋线）。

实测还在跑，欢迎你拿自己的稿子试，把不灵的地方提 issue。

## 手感怎么调

引擎设置里这几项各管一件事：

| 症状 | 动哪一项 | 怎么调 |
|---|---|---|
| 车轱辘话、那几句翻来覆去 | 频率惩罚 | 0.3 → 0.6 |
| 每章都在讲同一类事 | 存在惩罚 | 0.3 → 0.5 |
| 写得散、跑题、前后接不上 | 两项惩罚一起降 | 回到 0 ~ 0.2 |
| 通篇平淡、没有意外 | 核采样 + 温度 | 核采样 1.0 → 0.9，温度往上加 |

温度不是文笔，它只决定"有多大概率不选那个最稳的词"。改不出笔力，也改不出钩子。

这些参数只在取值非默认时才写进请求体；如果网关对陌生字段直接返回 400，
本次会话内会自动摘掉重发，不会每个请求都白试一次。

## 已知局限

写在前面，省得你踩：

- **不提供模型**，必须自备 OpenAI 兼容接口的 API Key。程序只做界面与上下文管理。
- **提示词层的反 AI 腔没有确定性兜底。** 模型不听话时照样会写出套话。
  现有「审校 + 按意见重写」与退化检测（连续无标点 / 重复过多）两道兜底，
  但仍是提示词层，不是像 InkOS 那样的确定性规则检测 + 定点修复。
- **小模型长输出会退化复读。** 实测某网关在长输出后半程会堆词到失控。补全设定
  已拆成逐节生成降低概率，开篇仍走单次流式；退化检测能拦截一部分，但换更强的
  模型才是最有效的解法。
- **只有中文界面**，没有 Web 端和移动端。
- **单人开发**，issue 响应可能不及时。

## 项目结构

```
theme.py        设计令牌与样式表（三套配色）
store.py        项目数据模型，单文件 JSON，存于 projects/
ai.py           流式续写、上下文装配、记忆压缩、设定分析、选中改写
presets.py      设定预设（内置 46 条 + 用户自定义）
ui.py           界面
main.py         入口
smoke_test.py   冒烟测试（114 项，需 PyQt6）
.github/        CI：冒烟测试 + 静态检查
build.bat       Windows 打包脚本
screenshots/    README 用截图
```

改动后跑一遍测试：

```bash
python smoke_test.py
```

测试会真实实例化主窗口与各个弹窗，验证改写现场、删章重定位、去重算法、
快照回滚、段落格式一致性、自动审校逻辑、采样参数收发规则，全程在临时目录里进行，
不会碰你的作品库。

## 数据与备份

作品存于程序目录下的 `projects` 文件夹，每部一个 JSON。每次保存前自动留一份快照在
`projects/backup`，保留最近 40 份。标题栏「作品 → 历史版本」可以逐份查看并回滚，
回滚前会再存一份当前状态。

自动保存是 8 秒一跳，但**同一份快照 60 秒内不重复生成** —— 否则四十份回滚点实际
只覆盖几分钟，而历史版本的用处恰恰是「回到一小时前删掉的那段」。节流之后四十份
能铺满约 45 分钟的连续写作。「一次生成写完 / 被打断」、「改稿完成」、「切换作品前」、
「回滚前」这四种里程碑不受节流影响，各留一份。

**换机器**：用「导出 → 项目备份」拷 json，在另一台机器「作品 → 导入备份」。

注意 `projects/` 里含 API Key 与小说正文，所以它在 `.gitignore` 里。
